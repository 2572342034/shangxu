一、产品概述

商序云是一套面向 B2B 销售团队的销售运营平台，把「线索获取 → 客户经营 → 商机推进 → 合同签订 → 订单履约 → 开票出库 → 应收回款 → 退货退款」串成一条链路。与只记录客户资料的轻量 CRM 不同，商序云同时管理履约与资金：每一笔钱从哪张单来、冲了哪张应收、还剩多少预收，都能追到底。

1.1 业务链路

线索 ─转化─▶ 客户 ─▶ 商机 ─赢单─▶ 合同 ─▶ 订单 ─┬─▶ 发货计划 ─▶ 出库单 ─┐
                                              ├─▶ 开票（发票）        ├─▶ 应收单 ─▶ 收款单 ─▶ 核销
                                              └─▶ 退货退款 ◀──────────┘

1.2 三条铁律

1. 订单必须审核通过才能生成出库单、应收单，避免未审先发。

2. 收款单是唯一记账入口：合同回款计划只是「计划」，实际收款一律通过收款单登记并核销到应收单。

3. 状态由核销结果推导：应收余额、订单收款状态、合同回款状态都由核销自动回写，不需要手工改。

四、客户管理

4.1 客户列表

支持按名称/编号/手机号搜索，按客户级别、行业、公私海筛选。列表展示客户名称、级别、行业、负责人、下次跟进时间等。

  • 我的客户 / 公海客户：右上角切换。公海客户对所有销售可见，领取后进入个人私海。
  • 领取：公海客户点击「领取」，负责人变更为当前用户。
  • 转移：把客户转给其他销售。
  • 放入公海：释放客户，供团队重新领取。

4.2 客户 360

点击客户名称打开右侧抽屉，一屏查看该客户全貌：

顶部统计条展示联系人数量、商机数量、商机总额、合同总额、跟进次数。

4.3 附件

在客户 360 的「附件」标签页点击「上传附件」，支持 PDF、图片、Office 文档、压缩包等，单个文件不超过 20MB。点击文件名可直接下载，上传人可删除。

五、联系人

管理客户侧的具体对接人：姓名、所属客户、职位、手机、邮箱、是否关键联系人。

  • 关键联系人用于标记决策链上的核心角色，商机推进时优先参考。
  • 支持按客户、姓名、手机号检索。

六、线索管理

线索是尚未确认价值的原始商机信息。

6.1 线索状态

新线索 → 跟进中 → 已确认 → 已转化 / 无效

6.2 线索转化

点击「转化」，系统按填写内容一次性生成：

  • 一个客户（可指定客户名称与级别）
  • 一个联系人（来自线索联系人信息）
  • 一个商机（可选，填写商机名称与金额）

转化后线索状态变为「已转化」，并记录转化目标客户。

注意：已转化的线索不能重复转化，避免产生重复客户。

八、交易管理

交易管理是系统的核心，包含 8 个子模块。建议按「总览 → 合同 → 订单 → 发货 → 出库 → 开票 → 应收 → 收款」的顺序理解。

8.1 交易总览

一屏看全局：合同签订额、订单额、已出库额、应收未收、已回款、已开票金额；交易趋势图；交易流水（合同、订单、出库、收款、开票、退款六类事件按时间合并）；客户交易排行；链路待办。

交易流水支持按类型筛选，是排查「这笔钱怎么来的」最快的入口。

单据流转与审批规则（合同 → 订单 → 出库 → 应收 → 收款 → 开票）：

单据状态流转关键规则
合同草稿 → 审批中 → 已审批 / 已驳回 → 已签订（可作废）金额由明细汇总；下单额度受合同金额约束
订单草稿 → 审批中 → 已审核 / 已驳回 → 已取消只有草稿/已驳回可编辑；关联合同时校验状态、客户、剩余额度
出库单待出库 → 待审核 → 已审核 → 已出库 → 已签收审核前不能确认出库；审核通过时自动生成应收单（已存在则跳过）
应收单待确认 → 已确认 / 已驳回（与收款状态并行）只有「已确认」的应收才能登记收款核销
收款单已确认 → 已作废唯一记账入口，核销后回写应收余额、订单收款状态、合同回款进度
发票待开票 → 已开票 → 已作废独立于收款；校验「累计开票 ≤ 订单/合同金额」，防超开

先货后款与先款后货：出库审核通过自动生成应收，对应「先货后款」；如果是预收款场景，可在应收页用「由合同生成」提前开应收，覆盖「先款后货」。

8.2 合同管理

状态流转：草稿 → 审批中 → 已审批 / 已驳回 → 已签订，也可作废。

  • 新建合同时按 5:5 自动生成两期回款计划，可手工调整期数与金额。
  • 合同详情抽屉展示合同基本信息、回款计划、附件。
  • 重要：回款计划只表达「计划」，不参与记账。合同详情中的「已回款」来自该合同下所有应收单的核销汇总。

回款登记：在合同详情点击某期计划的「回款登记」，系统会自动找到该合同的未结清应收单（没有则先按合同金额生成一张），把本次回款核销进去，并生成一张正式收款单。

合同明细：合同表单新增「合同明细」表格，可逐行添加产品/服务、单位、数量、单价，金额自动计算。

  • 有明细时，合同金额自动等于明细合计且不可手改（表单里会置灰并提示「已按明细合计自动计算」），避免金额与标的不符。
  • 不填明细时保留手填金额，适合框架合同（按实际下单结算）。
  • 合同详情展示「合同明细」区块，与下单进度、回款计划并列。
  • 合同金额变化后回款计划不会自动重算；如果计划合计与合同金额不一致，详情会显示黄色提示，需手动调整期数或金额。

合同额度与下单管控：合同详情新增「下单进度」，显示合同金额、已下单金额（该合同下未取消订单的合计）和剩余可下单金额。

  • 订单关联合同时，系统强制校验三件事：合同必须是「已审批」或「已签订」；订单客户必须与合同客户一致；订单金额不得超过合同剩余可下单金额。
  • 订单表单的「关联合同」是下拉选择，只列出该客户下可下单的合同，选中后显示「合同金额 / 已下单 / 剩余」；明细合计超过剩余时红色提示并禁止保存。
  • 不关联合同的订单仍可创建（小额直单），一旦关联就受上述规则约束。
  • 合同金额变更后剩余额度实时重算。
  • 不可下单的合同不会消失，而是在下拉里置灰并标注原因（如「合同草稿，需先审批或签订」「已超额 59880.00」），避免出现「找不到合同」的困惑；该客户一张合同都没有时会提示先去创建。

8.3 订单管理

状态流转：草稿 → 审批中 → 已审核 / 已驳回 → 已取消。

  • 订单支持明细行：选择产品自动带出单价，数量 × 单价自动算金额，合计实时汇总。
  • 关联合同：下拉选择，仅显示该客户下已审批/已签订且有剩余额度的合同；关联后校验客户一致与金额不超合同剩余额度，不关联则视为独立订单。
  • 只有已审核订单才能生成发货计划、出库单、应收单、发票。
  • 订单列表展示「出库状态」「收款状态」，均由下游单据自动回写。

8.4 发货计划

针对已审核订单安排发货：计划日期、计划数量（默认汇总订单明细）、仓库。

  • 状态：待发货 → 已发货 / 已取消。
  • 点击「生成出库单」把计划转为正式出库单，计划状态变「已发货」并回写出库单号。
  • 已生成出库单的订单不会出现在可选订单中，避免重复发货。

8.5 出库管理

由发货计划或订单生成，自动带出明细、收货人、收货地址。

  • 状态：待出库 → 已出库 → 已签收，可作废。
  • 支持维护物流公司与运单号。
  • 确认出库后回写订单出库状态：未出库 / 部分出库 / 已出库。

8.6 开票管理

从订单或合同发起开票申请，自动带出客户、抬头、金额。

  • 发票类型：增值税专用发票、普通发票、电子发票。
  • 税额按价税合计倒算：税额 = 金额 ÷ (1 + 税率) × 税率。
  • 状态：待开票 → 已开票 → 已作废。确认开票时录入发票号与开票日期。

8.7 应收管理

应收单是「客户欠我们多少钱」的凭证，来源为订单或合同。

  • 顶部统计：应收总额、已收款、未收款、逾期未收（含张数）。
  • 账龄列显示逾期天数，逾期单据标红。
  • 状态：未收款 / 部分收款 / 已收款，由核销结果自动计算。

注意：应收单不允许手工修改已收金额，收款必须走「收款核销」。

8.8 收款核销（核心）

收款核销是资金记账的唯一入口。

操作步骤

1. 进入「交易管理 → 收款核销」，点击「登记收款」。

2. 选择客户，填写收款金额、收款日期、收款方式（银行转账/现金/承兑汇票/在线支付/其他）、收款账户、凭证号。

3. 系统自动列出该客户未结清的应收单。勾选要冲销的应收单，默认按剩余金额核销，可手工调整。

4. 页面实时显示「已分配 / 收款金额」，分配额不能超过收款金额。

5. 确认登记后，系统在同一事务内完成：生成收款单 → 写入核销明细 → 更新应收已收金额与状态 → 回写订单收款状态与合同回款状态。

预收款

不勾选任何应收单直接保存，整笔记为预收款（预收余额 = 收款金额）。后续在列表点击「核销」，选择应收单与金额即可继续核销。

作废与冲销

点击「作废」会把该收款单已核销的金额逐笔反向冲回对应应收单，应收余额恢复到核销前，订单与合同状态同步回退。作废单保留记录，状态显示「已作废」。

核销规则

规则说明
不能超额核销单张应收的核销额不得超过其剩余金额
不能跨客户收款单与应收单必须属于同一客户
不能重复同一张收款单不能对同一应收单重复核销
可一冲多一张收款单可拆成多条核销明细，冲多张应收
并发保护采用乐观锁，两人同时操作同一应收单时后者会提示刷新重试

8.9 退货退款

关联订单创建退货单：退货日期、退货数量、退货金额、退款金额、退货原因。

  • 状态：待审核 → 已通过 / 已驳回 → 已退款。
  • 校验：退款金额不得大于退货金额。
  • 确认退款时记录退款时间，退款金额在交易流水中以红色标记。

九、产品目录与产品管理

9.1 产品目录

「产品目录」是左侧菜单中的独立页面，与「产品管理」分开：目录页管树和目录内产品，产品页管全部产品的列表与档案。

页面左侧是两级树形目录，默认分为「软件产品 / 实施服务 / 运维与部署 / 硬件设备」四大类，共 11 个节点，节点右侧显示该目录下的产品数量。右侧上半部分是当前目录的信息卡（名称、编码、状态、本级产品数、含子目录数、子分类数、排序、备注），下半部分是该目录下的产品列表。

  • 筛选：点击任意目录，右侧只显示该目录及其子目录下的产品；点击「全部产品」恢复。
  • 新增分类：点击目录右上角「+ 根目录」创建一级目录；或鼠标移到节点上，点右侧「⋯」→「新增子分类」。
  • 目录内新增产品：在目录页点「新增产品」，表单会自动预选当前目录。
  • 编辑 / 停用 / 删除：同样在「⋯」菜单中操作。停用后节点名称置灰并加删除线；有子分类或有产品的目录不能删除，需先移走。
  • 顶部支持按名称筛选目录节点。

十二、导入导出

12.1 导出

  • 客户列表：点击「导出」，下载 CSV（UTF-8 BOM，Excel 可直接打开，中文不乱码）。
  • 线索、应收：通过接口 /api/data/export/leads、/api/data/export/receivables 导出同结构 CSV。
  • 导出受数据权限限制：销售专员只能导出自己的数据。

12.2 导入导出产品

产品页提供「导入」「导出」两个按钮：

1. 点「导入」→「下载导入模板」，得到 13 列 CSV：产品编码、产品名称、所属目录、规格型号、单位、销售价、成本价、最低成交价、税率(%)、排序、状态、产品描述、备注。

2. 产品编码留空会自动生成；「所属目录」按分类名称匹配，名称不存在会跳过该行并提示先去产品目录页创建。

3. 重名产品、重复编码、格式错误的行会跳过并在弹窗中逐行列出原因。

4. 「导出」的产品 CSV 列顺序与模板完全一致，可在 Excel 里改完直接导回，适合批量调价。

12.3 导入客户

1. 准备 CSV 文件，首行为表头，列顺序：客户名称,级别,行业,来源,电话,城市,地址,备注。

2. 客户名称必填；重名客户自动跳过并在结果中提示。

3. 点击客户列表「导入」，选择文件。

4. 系统返回成功条数、跳过条数，并列出未导入原因。

提示：Excel 文件请先「另存为 CSV UTF-8」。

12.4 批量导出中心

左侧菜单「系统管理 → 数据导出」，也可从客户、线索、应收、产品列表页点「批量导出」直接进入（会自动选中对应类型）。原来的「导出」按钮仍保留，用于一键导出全量。

区域能做什么

  • 导出的行与列完全按界面选择，不再是固定全量；结果仍是带 UTF-8 BOM 的 CSV，Excel 直接打开不乱码。
  • 所有码值（级别、行业、状态、来源类型等）走统一字典转中文，与修改记录、快速导出口径一致。
  • 数据权限照常生效：业务员只能查到并导出自己数据范围内的客户/线索/应收；产品为主数据，不受负责人限制。
  • 单次导出上限 10000 条，超过请先缩小时间或筛选范围。

十三、修改记录与客户历史视图

13.1 全模块修改记录

系统会自动记录所有核心单据的字段级变更，不需要人工填写。覆盖客户、联系人、线索、商机、合同、订单、出库单、发货计划、发票、应收单、收款单、退货单、产品、产品目录与跟进记录。

记录内容说明
时间 / 操作人谁在什么时候改的
操作修改、新建、删除、领取、转移、放入公海、自动回收
字段显示中文名（如「负责人」「客户池」「单价」）
变更前 / 变更后状态值自动翻译成中文（如「私海 → 公海」）

三种查看方式：

1. 任意列表页的操作列点「记录」，弹出该单据的全部变更。

2. 客户 360、合同详情、产品详情里都有「修改记录」标签页。

3. 左侧菜单「系统管理 → 修改记录」进入全量检索中心，可按模块、单号、字段、操作人、变更值筛选。

记录由后端切面在更新前后自动比对数据库快照生成，业务代码无需改动；记录失败只写告警日志，不影响正常操作。技术字段（id、创建时间、version 等）不记录。

码值统一显示中文：字段名（性别、关键联系人、状态、客户池等）与取值（男/女、是/否、跟进中、A类（重点）、私海/公海、负责人姓名等）都由统一字典服务翻译，数据字典 sys_dict 里新增的项会自动生效，无需改代码。PART 这类在不同模块含义不同的码值会按业务类型区分（应收单显示「部分收款」、回款计划显示「部分回款」、出库进度显示「部分出库」）。CSV 导出同样输出中文，导入时会自动把中文还原成系统码值，两种写法都兼容。

13.2 历史客户与只读规则

客户被转移负责人、放入公海后被他人领取、或被定时任务自动回收后，原负责人并不会彻底失去这条客户：

  • 「我的客户」里不再显示（保证同一时刻只有一个负责人，避免撞单）。
  • 「历史客户」标签里仍能看到摘要：客户名称、编号、级别、行业、当前负责人、状态。
  • 敏感信息全部隐藏：电话、网站、省市区、详细地址、备注、简称、规模、跟进时间。
  • 客户 360 详情显示橙色提示「该客户已移交，仅可查看摘要」，不展示联系人、商机、合同、跟进记录与金额，附件只能下载不能上传或删除。
  • 编辑、删除、转移、放入公海、再次领取、新增联系人与跟进记录全部被后端拒绝，前端按钮也会隐藏。

修改记录对此类用户同样过滤敏感字段的历史值，避免通过审计日志绕过脱敏。

十四、系统管理

13.1 用户管理

新增/编辑用户：账号、姓名、手机、邮箱、部门、岗位、角色、状态。支持重置密码。

13.2 角色权限

角色由两部分组成：

  • 功能权限：菜单与按钮级权限，权限树按模块分组（工作台、客户、线索、商机、交易、收款、产品、系统等）。
  • 数据权限：全部数据 / 本部门及下属 / 仅本人。

新建角色时勾选权限树，保存后该角色下所有用户即时生效（登录态中的权限每次请求校验）。

13.3 部门管理

树形结构维护组织架构，支持多级部门。部门影响数据权限的「本部门及下属」范围。

13.4 数据字典

维护各类下拉选项与状态标签，如客户级别、行业、来源、合同状态、收款方式等。修改字典后前端标签自动更新。

13.5 操作日志

记录所有写操作：操作人、模块、类型、请求地址、IP、耗时、参数、异常信息。支持按模块与类型筛选，是排查「谁改了这张单」的依据。

十五、权限模型

系统采用「功能权限 + 数据权限」双层控制：

层级控制点示例
功能权限菜单可见性、按钮可见性、接口调用没有 crm:payment:cancel 就看不到「作废」按钮，直接调接口返回 403
数据权限列表与详情的可见范围销售专员只能看到自己负责的客户、订单、应收、收款

公海例外：公海客户对所有销售可见，不受数据权限限制。

十八、常见问题

Q1：登录提示「账号或密码错误」，日志显示「登录失败: null」

多为数据库连不上或库名错误。检查 MYSQL_DB 是否为 shangxu_crm（下划线），并确认库已初始化。

Q2：登录后页面 500 / 提示「系统繁忙」

检查 Redis 是否启动（redis-cli ping 应返回 PONG），以及前端代理是否指向正确的后端端口。

Q3：收款登记提示「核销金额超过应收余额」

应收单可能已被其他收款单核销。刷新页面后查看该应收的「已收金额」，按剩余金额重新填写。

Q4：作废收款单后，订单收款状态没变？

作废会同步回写。若未变化，检查该订单是否还有其它收款单在核销，状态按汇总结果计算。

Q5：上传附件失败

检查文件大小（≤20MB）与类型（PDF/图片/Office/压缩包等），并确认 CRM_UPLOAD_DIR 目录可写。

Q6：客户突然变成公海

公海回收任务把超过 30 天未跟进的私海客户自动回收。重新领取即可；如需关闭，将 CRM_POOL_RECYCLE_DAYS 设为 0。

Q7：导入客户全部失败

确认 CSV 为 UTF-8 编码、首行是表头、第一列是客户名称且不为空。
