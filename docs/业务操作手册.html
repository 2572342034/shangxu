一、这本手册解决什么问题

项目里另有一本《使用手册》，按菜单逐个讲功能按钮；本手册按业务场景讲「谁、在什么时候、为了什么、点哪里、产出什么单据」，适合新员工上手、岗位交接，以及搞清楚"为什么要有这张单"。

1.1 角色与职责

角色核心职责主要使用的功能
业务员找客户、跟进、推进商机、下单工作台、线索、客户、联系人、跟进记录、商机、订单
销售经理带团队、看预测、审批商机看板、合同审批、订单审核、业绩排行
销售总监看全局、定目标、管异常工作台、交易总览、业绩排行、数据权限 ALL
财务开票、记欠款、收钱对账开票管理、应收管理、收款核销、退货退款
产品 / 销售运营维护可售清单与价格产品目录、产品管理、批量导入
系统管理员账号、权限、字典、日志系统管理全部模块

1.2 权限与业务分工

系统用「功能权限 + 数据权限」双层控制：前者决定按钮是否可见、接口能否调用，后者决定能看到谁的数据（全部 / 本部门及下属 / 仅本人）。

业务员默认只有产品与目录的查看权，没有新增、编辑、删除权。这不是功能缺失，而是主数据治理的常规做法：产品定价、成本、目录结构属于公司主数据，应由产品或销售运营统一维护；业务员只负责在订单里选用产品。若贵司确需业务员建档，由管理员在「角色权限」页勾选 crm:product:add 等权限点即可，无需改代码。

二、业务全景

2.1 五个阶段

1 获客    线索 → 客户 → 联系人      把陌生信息洗成可跟进的客户档案
2 售前    商机 → 合同 → 回款计划    判断能不能成、值多少钱，谈定条款并签约
3 履约    订单 → 发货计划 → 出库单  把合同拆成可执行的交付指令并发货
4 结算    发票 → 应收单 → 收款核销  开票、记欠款、收钱并冲对具体账目
5 售后    退货退款单                处理退货退款，同时保证历史单据可追溯

2.2 单据速查

单据回答的业务问题通常谁维护
线索这个人可能买吗市场、业务员
客户 / 联系人跟谁签合同、找谁谈业务员
跟进记录上次聊了什么、下次何时跟业务员
商机这单能成吗、值多少钱、卡在哪业务员、销售经理
合同 + 回款计划法律上约定什么、预计何时收钱销售、法务
订单 + 发货计划 + 出库单交付什么、哪天发、真发了没商务、仓储
产品目录 / 产品卖什么、多少钱、成本多少产品、销售运营
发票客户拿什么入账报销财务
应收单 / 收款单 / 核销欠多少、到账多少、冲哪笔财务
退货退款单退了什么、退了多少钱售后、财务

三、场景一：从陌生线索到签约（业务员）

3.1 录入线索

  • 路径：线索管理 → 新建线索；或顶部「快速新建」→ 新建线索
  • 目的：把展会名单、官网留资、转介绍等未验证信息登记进系统，避免散落在个人微信和 Excel
  • 填写：姓名/公司、联系人、手机、来源、行业、备注
  • 产出：状态「新线索」的线索记录

3.2 跟进并确认价值

  • 每次沟通后到「跟进记录」登记方式与内容，并填下次跟进时间
  • 线索状态推进：新线索 → 跟进中 → 已确认
  • 到期未跟进会由定时任务推送提醒；私海客户超过 30 天无跟进会被自动回收进公海
  • 客户被移交、被他人领取或自动回收后，原负责人在「历史客户」里仍能看到脱敏摘要，但不能再编辑、领取或转移；这样既保留交接记忆，又保证同一时刻只有一个负责人

3.3 转化为客户

  • 路径：线索列表 → 转化
  • 系统动作：一次性生成一个客户 + 一个联系人，可勾选同时生成商机
  • 产出：客户档案（交易主体）、联系人（具体对接人）、可选商机
  • 注意：已转化线索不能重复转化，避免产生重复客户

3.4 建立并推进商机

  • 路径：商机管理 → 新建；填写客户、名称、预计金额、阶段、预计成交日
  • 阶段的业务含义：接洽（10%）→ 需求（30%）→ 报价（50%）→ 谈判（70%）→ 赢单（100%）/ 输单（0%）
  • 管理层靠阶段与金额做销售预测，因此阶段不要跳级、金额不要随意改
  • 「看板视图」可拖拽卡片推进阶段，列头显示各阶段商机数量与金额合计

3.5 赢单后签合同

  • 路径：合同管理 → 新建，关联客户与商机，填金额、签约日期、周期
  • 状态：草稿 → 审批中 → 已审批 / 已驳回 → 已签订
  • 系统按 5:5 自动生成两期回款计划（可改），它表达"预计什么时候收钱"，不是实际收款
  • 产出：具备法律效力的合同，以及后续订单的依据

四、场景二：从合同到发货（商务 / 仓储）

4.1 建订单

  • 路径：订单管理 → 新增产品订单；或合同详情中发起
  • 目的：合同往往分批发，订单把合同拆成"这次具体交付什么"
  • 明细行：选择产品自动带出单价，数量 × 单价自动算金额，合计实时汇总

4.2 提交审核

  • 状态 草稿 → 审批中 → 已审核 / 已驳回
  • 红线：只有已审核订单才能生成发货计划、出库单、应收单、发票，防止未审先发

4.3 排发货计划

  • 路径：发货计划 → 新建，选择已审核订单，填计划日期、数量、仓库
  • 回答"哪天发、发多少、从哪个仓"
  • 已生成出库单的订单不会再出现在可排计划列表里，避免重复发货

4.4 生成出库单并确认

  • 计划点「生成出库单」，或订单详情直接生成；系统自动复制明细、带出收货人与地址
  • 状态 待出库 → 已出库 → 已签收，维护物流公司与运单号
  • 确认出库后，订单的「出库状态」自动变为 未出库 / 部分出库 / 已出库

五、场景三：从交付到收钱（财务）

5.1 三张单据各管一件事

单据业务含义是否影响应收余额
发票给客户入账报销的税务凭证否
应收单客户欠我多少（内部账）是，记录欠款
收款单钱真到账（银行流水凭证）是，通过核销冲减

开发票不等于收到钱，也不改变应收余额；只有收款单核销才会减少欠款。

5.2 开票

  • 路径：开票管理 → 申请开票 → 选订单或合同 → 生成待开票记录
  • 税额按价税合计倒算：税额 = 金额 ÷ (1 + 税率) × 税率
  • 确认开票时录入发票号与开票日期，状态变「已开票」；可作废

5.3 生成应收单

  • 路径：应收管理 → 由订单 / 由合同生成；也可在订单详情一键生成
  • 应收金额默认取来源单据金额，应收日期默认单据日期 + 30 天
  • 列表提供账龄与逾期天数，逾期金额标红

5.4 登记收款并核销

  • 路径：收款核销 → 登记收款
  • 填客户、金额、日期、方式（银行转账 / 现金 / 承兑汇票 / 在线支付）、账户、凭证号
  • 系统列出该客户未结清应收，勾选后默认按剩余金额核销；不勾选则整笔记为预收款
  • 保存后在同一事务内完成：生成收款单 → 写核销明细 → 更新应收已收金额与状态 → 回写订单收款状态与合同回款状态

5.5 预收与作废

  • 预收余额可在列表点「核销」继续冲抵后续应收
  • 作废收款单会逐笔反向冲销，应收余额与订单/合同状态同步回退
  • 核销规则：不能超额、不能跨客户、同一应收不能重复核销、一单可冲多张应收

5.6 三条账务铁律

1. 收款单是唯一记账入口；合同回款计划只表达计划，不参与记账

2. 状态由核销结果推导，不要手工改应收已收金额

3. 合同实收 = 该合同下所有应收单的核销汇总，不是回款计划的累加

六、场景四：退货退款（售后 + 财务）

  • 路径：退货退款 → 新建退货单，关联订单，填退货日期、数量、金额、退款金额、原因
  • 状态：待审核 → 已通过 / 已驳回 → 已退款
  • 校验：退款金额不得大于退货金额
  • 确认退款时记录退款时间，退款金额在交易流水中标红
  • 删除保护：已被订单明细引用的产品不能删除，只能「停售」，保证历史单据仍可追溯当时卖的规格与价格

七、场景五：产品与目录维护（产品 / 销售运营）

7.1 维护目录

  • 路径：左侧菜单「产品目录」（独立页面）
  • 左侧两级树可新增根目录 / 子分类、编辑、停用、删除；右侧显示目录信息卡与该目录下产品
  • 有子分类或有产品的目录不允许删除

7.2 新增产品

  • 路径：产品管理 → 新增产品；或在目录页点新增（会自动预选当前目录）
  • 必填仅三项：产品名称、销售价、产品编码（留空自动生成 PRD + 4 位序号）
  • 选填：所属目录、规格、单位、成本价、最低成交价、税率、排序、状态、描述、备注
  • 表单底部实时显示预估毛利率；最低成交价不得高于销售价

7.3 批量导入 / 调价

  • 产品页「导入」→「下载导入模板」，按 13 列填写 CSV
  • 编码留空自动生成；所属目录按分类名称匹配，名称不存在会跳过并提示
  • 重名、重复编码、格式错误逐行列出原因
  • 「导出」的 CSV 与模板同列序，可在 Excel 改完直接导回，适合批量调价

八、各岗位日常 SOP

8.1 业务员的一天

1. 打开工作台：看 KPI、待办（待跟进客户 / 待出库 / 待收款 / 待审批）、最近跟进

2. 处理消息通知（铃铛）：逾期应收、跟进到期、公海回收提醒

3. 按「下次跟进时间」联系客户，沟通后补跟进记录并设下次时间

4. 在商机看板推进阶段，更新金额与预计成交日

5. 赢单后建合同、下订单，之后交给商务与财务

8.2 销售经理的一天

1. 看商机看板与业绩趋势，识别卡在某阶段过久的单子

2. 审批合同、审核订单

3. 用「本部门及下属」数据范围检查团队客户与商机

4. 检查公海客户，重新指派

8.3 财务的一天

1. 看应收管理中的逾期未收，按账龄催款

2. 处理待开票申请，确认开票

3. 收到款后登记收款单并核销

4. 复核预收余额、作废单，必要时导出应收 CSV 对账

8.4 自动任务时间表

时间任务业务作用
09:00逾期应收提醒催收，缩短回款周期
09:05跟进提醒提醒 24 小时内到期的跟进
09:10公海回收超过 30 天未跟进的私海客户放回公海

多实例部署时只让一个实例开启定时任务，避免重复推送。

九、业务红线速查

规则业务原因系统如何拦截
只有已审核订单可生成下游单据防止未审先发、未审先开票生成接口校验订单状态
收款单是唯一记账入口防止合同计划与应收重复计收旧回款入口内部转调收款单
不能超额 / 跨客户 / 重复核销保证账实相符核销时逐条校验并提示
最低成交价 ≤ 销售价折扣管控保存时校验
被引用的产品不能删历史订单可追溯删除时检查订单明细
有子分类/产品的目录不能删防止产品变孤儿删除时检查子节点与产品
产品编码唯一主数据唯一性数据库唯一索引 + 保存查重
两人同改同一单据需刷新防并发覆盖乐观锁版本号校验

十、常见业务口径问答

Q：合同已经签了，为什么"已回款"还是 0？

回款计划只是预计收款时间；实际收款必须登记收款单并核销到应收单，合同实收才会变化。

Q：发票开完了，为什么应收还没结清？

发票是税务凭证，不代表钱到账。需登记收款单核销。

Q：客户一次打了 50 万，覆盖三张应收，怎么记？

登记一张 50 万的收款单，勾选三张应收分别填核销金额即可；剩余部分留作预收。

Q：钱记错了怎么办？

作废该收款单，系统会逐笔反向冲回，再重新登记。不要手工改应收金额。

Q：业务员为什么看不到"新增产品"？

角色只授予了产品查看权（见 1.2）。需要开放时由管理员在角色权限页勾选。

Q：客户被别人领走了，我还能看到吗？

A：能在「历史客户」标签看到名称和当前负责人等摘要，但电话、地址、备注、商机合同金额都已隐藏，且所有操作按钮不可用。这是主流 CRM 的做法：保留交接记忆，同时防止两个销售同时跟一家客户。想继续跟进请联系现负责人或让经理重新转移。

Q：客户突然跑到公海了？

超过 30 天未跟进被自动回收，重新领取即可；也可把回收天数设为 0 关闭。

Q：订单已出库，为什么还能看到"待发货"？

部分出库时订单状态是「部分出库」，剩余数量可再排一次发货计划。

Q：产品删除提示"已出现在订单明细中"？

该产品有历史交易，改为「停售」即可，历史订单仍保留当时的名称与价格。
